# InfoSlides MCP 1.10.2

Tool descriptions that now match what the InfoSlides API does when something is deleted. No tool, parameter or result shape changed.

## Fixed

- **`delete_slideshow` can be undone.** The InfoSlides API now returns an `undo` when a slideshow is deleted. Within 24 hours, `undo_change` brings it back with the schedule entries and screen pairings the delete removed, as long as the plan has room for it. The `delete_slideshow` and `undo_change` descriptions (local and hosted), the CLI help and the skill's `everyday-edits.md` said a slideshow delete could not be undone. They now say it can, and that `restore_slideshow` brings back the slideshow alone after the 24 hours.
- **`delete_slide` (local and hosted).** The description said the slide is removed permanently, though the result has always carried an undo. It now says the undo puts the slide back within 24 hours.
- **`delete_source` (local) and `infoslides source delete`.** The description said slides and tickers fed by the source stop updating. The API refuses the delete while any slideshow's slides or news ticker use the source, also when that ticker is turned off, and the error names those slideshows. The description now says so, and that the delete cannot be undone.

## Directory listings

Three hosted descriptions changed (`delete_slideshow`, `delete_slide`, `undo_change`). Rescan in the OpenAI portal after the host is redeployed, and refresh the descriptions in the Claude and Microsoft submissions that show them.
