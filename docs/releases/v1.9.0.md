# InfoSlides MCP 1.9.0

Tool results now come back in a form a program can read without parsing text, every tool says what its result looks like, and a push source key comes with a quick update link for updating a board by hand.

## New

- **Quick update link.** `create_source_key` now also returns `quickUpdateUrl`: a phone page with large buttons, no login, where a person updates a live board by hand (a gym receptionist counting people in, for example). Give the link to that person; revoking the key ends it. The CLI's `source key` prints it under the key.
- **Structured results.** Each tool that returns data now sends its result as `structuredContent` as well as the text block it always had. Both hold the same JSON: `data` (what the tool returns, an object, a list or null), plus `warnings` and `undo` when there are any. Clients that read only the text keep working unchanged. Error results are unchanged and carry no structured content.
- **Output schemas.** `tools/list` declares an `outputSchema` for every tool that returns that result: an object with a required `data`, and optional `warnings` and `undo`. For the tools whose result the server types (devices, slideshows, slides, sources, templates, keys, the workspace and so on) `data` is described field by field, with optional and nullable fields marked as such. The tools that pass the API's own JSON through describe `data` as any value, which is what they return. The four tools that return an image (`get_now_slide_png`, `preview_slide`, `preview_new_template`, `preview_brand`) have no output schema.
- **Check a slideshow.** New tool `check_slideshow` (CLI and hosted, including Claude and Muse): lists what will go wrong before a slideshow goes on a screen, such as no slides, a failed render, a live data slide with no source or a source that is off or failing, or a media file that failed to prepare. `ready` is false when any finding is an error; each finding has a message and a fix. It does not look at text size, expired content or the screen's shape.
- **Slideshow list pages.** `list_slideshows` (and `slideshows list --page`) now returns `items`, `total`, `page`, `pageSize` and `totalPages`, so a client can tell when it has every slideshow. It takes `page` and `pageSize`.
- **Muse.** The hosted server sends Muse its own guide, without the AI Studio tools.
- **Plainer tool descriptions.** `list_takeovers` and the media folder tools say what they do and return in plain words.
- **Clearer import message.** `import_slide` from a slideshow into itself now says a slideshow cannot import a slide from itself, instead of "not found or not shared". This comes from the website API.
- **Rate limit headers.** Every `/v1` response carries `RateLimit-Limit` and `RateLimit-Remaining`, so a client can slow down before it gets a 429. This comes from the website API.
- **Hosted server.** The hosted tool list and the public server card at `/.well-known/mcp/server-card.json` carry the same `outputSchema`. The schemas hold no description text.

## Under the hood

- One table, `ToolOutputSchemas`, maps each tool name to the type of its result. A test fails when a tool is missing from it or it names a tool that does not exist, and the four image tools are listed there as exempt on purpose.
- The schema is generated from the same source-generated serializer metadata the results are written with, so it works in the Native AOT build. It is attached to the registered tools once, in `WithInfoSlidesTools`, which both the local and the hosted server call.
- A test builds a real result for every typed tool from a sample of the API's JSON, with nulls for optional fields, and validates it against that tool's schema (JsonSchema.Net, test project only).

- Releases are checked with `scripts/check-release-sync.ps1`: one line per surface (git tag, GitHub release, registry listing, hosted server card and `initialize` version) saying whether it matches the release. Tests now fail when a tool is mentioned in neither the skill nor `agents.md`, or when a hosted tool has no description or an untyped parameter.

## Upgrade

The result of `list_slideshows` changed shape (a page with `items` instead of a bare list), so a program that reads it directly needs the 1.9.0 build or later; the website API and the hosted server are deployed together for the same reason. Otherwise nothing to do. The local `infoslides` program, the Gemini CLI extension and the Claude and Antigravity plugins pick this up with the 1.9.0 build for your platform below. The hosted server at `https://infoslides.app/mcp` picks it up when it is redeployed.
