# InfoSlides MCP 1.8.0

Tools for almost everything the InfoSlides web app can do that the MCP server could not: source health and fetching, the brand guide, the media library, template upkeep, editing text slides, stock photos, Google Slides import, the audit trail and error log, restoring a deleted slideshow, removing a screen, broadcast channels, and team access. Agents can also follow InfoSlides releases now: read upcoming-update notices, see which version is running, and search the help articles, blog and release notes. 46 new tools in all, with a command line verb for each.

## New

### Billing

- **`get_billing`.** Which plan the workspace is on and when it renews: the plan with its prices, the status (free, active, cancelling, paused, past_due, cancelled or suspended), `renewsAt`, `endsAt` when a cancellation is scheduled, and what is used against each limit (slideshows, devices, users, storage). Read-only and without card data; changing the plan stays in the web app. Needs a workspace admin key. On the command line: `infoslides billing show`.

### Live data sources

- **Source health.** `list_sources` and `get_source_status` now return `health` (`Healthy`, `Degraded` after one or two failed fetches in a row, `Failing` after three or more), `lastError` in plain words, `consecutiveFailures` and `lastSuccessAt`.
- **`fetch_source_now`** fetches a source right away; the fetch runs in the background, so read `get_source_status` a few seconds later.
- **`get_source_items`** shows the latest items a source has fetched, newest first, with an optional `limit` of 1 to 100.
- **`test_source_config`** tries an adapter and its settings against the live service without saving anything. A failed test is a normal answer with `success: false` and the reason.
- **`get_source_fields`** lists the fields a source's items have (`key`, `label` and a `sample` value), for mapping a source to a template.
- **`add_weather_alert_timeline`** adds a set of 8 live data slides from a Weather alert source, one per 6 hours over the next 48 hours, each hiding itself when there are no alerts. One undo token removes all 8.

`fetch_source_now` and `test_source_config` are limited to 10 calls a minute per workspace.

### Brand guide

- **`get_brand_guide`** reads the guide slides are made from (`inUse`) and the working copy (`draft`), and says whether a person still has to confirm the draft.
- **`update_brand_guide`** replaces the draft. It never changes what slides use: a person confirms it on the Brand page.
- **`upload_brand_logo`** puts a logo image from disk (up to 5 MB) into the draft, for light or dark backgrounds or as a small square mark.
- **`preview_brand`** draws a sample slide from the draft or the confirmed guide as an image, and **`list_brand_previews`** lists the sample names.
- **`check_brand`** checks a slideshow against the confirmed guide, slide by slide: colours outside the palette, text that is hard to read, a missing logo, banned phrases and other fonts. Advisory only.

### Media library

- **`get_upload_limits`** returns storage used, allowed and free, the largest file and the accepted file types, so a large upload can be checked before it is sent. `upload_media` now mentions it.
- **`list_media`** browses the library (filter by folder, type and name; paged; with storage figures), and **`get_media`** reports whether an upload is ready, with progress while a video is prepared.
- **`update_media`** renames a file, moves it to a folder or back to the top level, and shares it with other workspaces or stops sharing it. **`delete_media`** deletes a file and is refused, with the slides named, while a slide uses it.
- **Folders:** `list_media_folders`, `create_media_folder`, `rename_media_folder` and `delete_media_folder` (an empty folder only).

### Templates

- **`get_template`**, **`update_template`** (title, HTML, CSS or the data fields; slides using it pick up the change), **`delete_template`** (refused while slides use it), **`clone_template`** (copy a built-in layout into the workspace to change it), **`get_template_usage`**, **`regenerate_template_thumbnail`** and **`list_template_categories`**. Built-in layouts cannot be changed or deleted; the error says to copy them first.

### Slides and slideshows

- **`get_slide_design`** and **`update_slide_design`** read and change a slide made with `add_designed_slide`. The whole design is sent back; the slide is drawn again in place and keeps its position, hidden state and rules, and the result carries an undo token.
- **`search_stock_images`** searches free stock photos (Unsplash) for a text slide background. `add_designed_slide` takes the chosen result as a new `stockPhoto` argument, which puts the photographer credit on the slide.
- **`import_google_slides`** makes a slideshow from a Google Slides presentation, with a Google access token the agent obtained from the person. The token is used for that one call and never stored.
- **`list_shared_slideshows`** and **`import_slide`** copy one page of a shared slideshow into another.
- **`restore_slideshow`** brings back a deleted slideshow with its slides and settings. Its schedules are not brought back. `delete_slideshow` and `undo_change` now say so.

### Screens and schedules

- **`update_schedule_entry`** changes a daily time window in place: what it plays, its times or its priority.
- **`delete_device`** removes a screen from the workspace, as the Devices page does, and returns an undo token that brings it back.
- **`create_broadcast_device`** creates a broadcast channel: one stream for any number of screens or a browser, with no pairing.

### Team, audit trail and errors

- **`deactivate_member`** and **`reactivate_member`** turn a person's access off and on without removing them. The last active admin cannot be turned off.
- **`get_audit_trail`** answers "who changed this?" (filter by thing, person, action, category and time), and **`get_error_log`** reads the workspace's error log as a workspace admin sees it in the web app. Both need a workspace admin key.

### Keeping the person informed

- **`get_platform_version`** returns the running InfoSlides release, the build, when it was deployed and the release notes of that version.
- **`get_platform_notices`** returns active notices from the InfoSlides team, such as an update or maintenance window and when it starts.
- **`search_articles`** searches the help articles, blog posts and release notes (free text, type, published since a date, or one release's notes), and **`get_article`** reads one as Markdown.

The skill and the server instructions describe the routine: tell the person when an update is coming, tell them when it is live and what changed once the release notes are published, and search the help articles before saying something cannot be done.

### Command line

Every new tool has a verb: `infoslides billing show`; `source fetch`, `source items`, `source test`, `source fields`; `brand show`, `brand set`, `brand preview`, `brand check`, `brand samples`, `brand logo`; `media limits`, `media list`, `media status`, `media edit`, `media delete`, `media folders`, `media folder-create`, `media folder-rename`, `media folder-delete`; `template categories`, `template show`, `template edit`, `template delete`, `template clone`, `template usage`, `template thumbnail`; `slide design`, `slide set-design`, `slide stock-search`; `slideshow restore`, `slideshow import-google`, `slideshow shared`, `slideshow import-slide`, `slideshow weather-alerts`; `schedule edit`; `device delete`, `device broadcast`; `team deactivate`, `team reactivate`; `workspace audit`, `workspace errors`; `platform version`, `platform notices`, `platform search`, `platform article`.

## Hosted profile

`get_platform_version`, `get_platform_notices`, `search_articles` and `get_article` join the hosted tool list for ChatGPT, Claude, Microsoft 365 Copilot and Muse on `https://infoslides.app/mcp`, with hosted descriptions that name no other tool. The hosted server lists 45 tools, four more than in 1.7.4.

The other new tools are on the local `infoslides` program, the command line, the Gemini and Antigravity extensions and API-key connections to the hosted server. They join the hosted profile once they have hosted wording and skill text. `upload_brand_logo` reads a file from disk, so the hosted server leaves it out for every caller, as it does the other file upload tools. The hosted `add_designed_slide` leaves out the new `stockPhoto` argument until `search_stock_images` is hosted too.

## Skill

The InfoSlides assistant skill (local and hosted variants, re-synced from the InfoSlides repository) and this repository's `SKILL.md` gained:

- Routing rows for the new tools: billing, team access, the audit trail and restoring a slideshow, upload limits, the media library, editing a text slide and stock photos, schedule edits, removing a screen, broadcast channels, Google Slides import, copying a page, the brand guide and source health.
- A "Keeping the person informed" section with the release routine above, in both variants.
- In `live-data.md`: source health, testing, fetching, items and fields, the weather alert timeline and template upkeep. The Claude plugin's copy is now in step with the others; it lacked the source health rows before.
- "When you cannot do it" no longer says Google Slides import is web app only on the local variant, and both variants now say to search the help articles first.
- Local variant: routing rows for removing a member and revoking an invite, API keys, the media folder tools, brand preview samples, template categories and redrawing a layout's thumbnail. `getting-started.md` and the Google Slides scenario describe `import_google_slides`, and the note that `get_template` and `get_media` have no MCP tool is gone (only `get_takeover` is left). REST-only names in the reference files now give the MCP tool beside them.
- Hosted variant: "Show this photo on the lobby screen" uses `show_media_on_device` and `get_show_status` (a temporary takeover) instead of adding a permanent slide.

## Fixed

- A tool call that leaves out a required argument, or sends one the tool does not take, is refused with `ValidationFailed` naming the argument (with its description, or with the list of arguments the tool takes) before anything is sent to the API. A missing argument used to answer only "An error occurred invoking", and an unknown one was dropped without a word.
- `create_template` in code mode sends an empty stylesheet when `css` is left out, so `css` is optional as the description says. The description now says to leave `sampleJson` out with `html`: the `{{field}}` placeholders are the fields.

## Under the hood

- The new tools pass the API's own JSON through, so new fields reach the agent without a release of this server. A new `SendFileAsync` on the API client sends one file as multipart for `upload_brand_logo`.
- A table-driven test calls each new tool against a fake backend and checks the method, path and body it sends. The command line test covers a verb from each group, and `update_media` with nothing to change is refused without a call.
- Tool count assertions, the destructive and open-world tool lists and the hosted rules (`hosted-rules.json`, synced from the InfoSlides repository) include the new tools.
- `feature/APX-59-source-tools` and `feature/BG-05-brand-tools` were merged into this release.

## Upgrade

The new tools call `/v1` routes the InfoSlides API added between 2026-10-16 and 2026-10-24; against an older API they answer a not-found error. Install the 1.8.0 build for your platform below, or update the Gemini CLI extension or the Claude and Antigravity plugins. The hosted server at `https://infoslides.app/mcp` picks up the changes when it is redeployed, with nothing to do on your side. Existing API keys and configuration keep working.
