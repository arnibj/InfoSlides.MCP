# InfoSlides MCP 1.8.0

Three tools and three command line verbs for working with live data sources, and source health on the tools that list them.

## New

- **Source health.** `list_sources` and `get_source_status` now return `health` (`Healthy`, `Degraded` after one or two failed fetches in a row, `Failing` after three or more), `lastError` in plain words (for example that a feed address was not found), `consecutiveFailures` and `lastSuccessAt`. The same information the Sources page shows with a warning icon is now available to an agent, so it can check a source before building a slide on it.
- **`fetch_source_now`.** Asks InfoSlides to fetch a source (RSS, weather, calendar) right away instead of waiting for its next scheduled fetch. The fetch runs in the background, so read `get_source_status` a few seconds later for the new health.
- **`get_source_items`.** Shows the latest items a source has fetched, newest first (`title`, `body`, `imageUrl`, `url`, `fetchedAt`, `expiresAt`), with an optional `limit` of 1 to 100. Use it to see what a slide on the source would show.
- **`test_source_config`.** Tries an adapter and its settings against the live service without saving anything, for example whether an RSS address works. A failed test is a normal answer with `success: false` and the reason, not an error. Use it before `create_source`.
- **Command line.** `infoslides source fetch <source-id>`, `infoslides source items <source-id> [--limit n]` and `infoslides source test <adapter-type> [--config json]`.

`fetch_source_now` and `test_source_config` are limited to 10 calls a minute per workspace.

## Skill and documentation

`SKILL.md`, the live data reference in `skills/` and the README describe the new tools and the health fields. The copy under `plugins/claude/skills/` has no matching table row and still needs updating.

## Not in the hosted profile yet

The three new tools are available on the local `infoslides` program, the CLI and the Gemini and Claude plugins. They are not in the hosted tool list for `https://infoslides.app/mcp` yet; they need hosted wording and skill text first, and will be added later for all hosted agents. The hosted descriptions of `list_sources` and `get_source_status` do mention the health fields.

## Under the hood

- The `Source` and `PushSourceStatus` models carry the new optional fields, so older servers that omit them still deserialize.
- Tool count assertions and the open-world tool list include the new tools. New tests cover the health fields, the three tools and the three command line verbs.

## Upgrade

The new routes (`POST /v1/sources/{id}/fetch`, `GET /v1/sources/{id}/items`, `POST /v1/sources/test-connection`) were added to the InfoSlides API in the same change set; against an older API the three tools answer a not-found error and the health fields are empty. Existing API keys and configuration keep working.
